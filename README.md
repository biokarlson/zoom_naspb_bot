# Zoom bot v1.1 — планирование встреч через Telegram

Telegram-бот на Python (aiogram 3): пользователи подают заявки на встречи, админ их одобряет,
бот создаёт встречу в Zoom и событие в Яндекс Календаре и отправляет автору инструкцию.
Одобренные встречи можно отменять (с удалением в Zoom и в календаре).

Все даты и время — по Москве (Europe/Moscow). Внутри время хранится в UTC.

## Возможности

- Заявка через диалог: название, комитет, дата, время начала, продолжительность (1–4 ч), повтор.
- Повтор только ежемесячный, по дню недели и номеру недели месяца (1-я, 2-я, 3-я, 4-я, последняя); можно выбрать несколько недель, окончания нет.
- Проверка занятости: встречи бота и события Яндекс Календаря, горизонт для серий 6 месяцев.
- Одна общая ссылка (личный номер Zoom, PMI) для всех встреч; при пересечении по времени автоматически создаётся отдельная комната (не PMI).
- Одобрение, отклонение, отмена (по запросу автора или администратором), защита от повторных нажатий.
- Шаблон сообщения с инструкцией, дополнительный текст отдельным сообщением, настраиваемые ссылки в инструкции.
- Настройка Zoom (OAuth) и Яндекс Календаря (CalDAV) прямо из бота.

## Как это работает

### Роли
- **Админ** — Telegram ID из переменной окружения `ADMIN_IDS` (можно несколько через запятую); если переменная не задана, используется запасной список в `config.py`. Все остальные — обычные пользователи, подать заявку может любой.
- Админ тоже может подавать заявки; одобряет их сам. Все админы получают заявки, обрабатывает первый нажавший.

### Меню и команды
- `/start` — главное меню («Заявка» / «Управление»). Постоянная кнопка «🏠 Главное меню» внизу экрана появляется после `/start`.
- `/request` — подать заявку, `/my` — «Мои встречи», `/cancel` — отменить текущее действие.
- «Управление» у пользователя — «Мои встречи». У админа — настройки: подключение Zoom и календаря, шаблон сообщения, дополнительный текст, ссылки в инструкции, «Все встречи».

### Заявка
1. Бот проверяет: Zoom подключён, календарь подключён, у пользователя не больше 2 заявок на рассмотрении.
2. Диалог: название → комитет → дата (`ДД.ММ.ГГГГ`) → время (`ЧЧ:ММ`) → продолжительность → повтор. Для повтора выбираются недели месяца (несколько, с галочками); день недели берётся из даты первой встречи. Если первая дата не подходит под правило, бот просит другую дату.
3. Проверка занятости (см. ниже). Если время занято и общей, и отдельной ссылкой, отправить нельзя: предлагаются «Выбрать другую дату» и «Связаться с админом». Если пересечение есть, но возможна отдельная ссылка — бот предупреждает, и заявку можно отправить.
4. Заявка получает статус «на рассмотрении», каждому админу уходит карточка с кнопками «Одобрить» / «Отклонить» / «Проверить занятость».

### Статусы
`на рассмотрении → одобрена → отмена запрошена → отменена`; `на рассмотрении → отклонена`; `на рассмотрении → отменена автором`.

### Одобрение
Одобрения выполняются по одному (общая блокировка), порядок такой:
1. Проверка занятости и выбор ссылки: общая (PMI) или отдельная комната.
2. Создание встречи в Zoom.
3. Создание событий в календаре. Для серий — сверка: бот читает календарь обратно на 12 месяцев вперёд и сравнивает с ожидаемыми датами; при неожиданном расхождении (лишние или пропущенные даты) всё откатывается, а если календарь не удалось прочитать, одобрение не блокируется и админ получает предупреждение.
4. Один атомарный `UPDATE` статуса вместе с ID встречи Zoom, ссылкой и UID/URL событий.

При сбое любого шага созданное откатывается, статус заявки не меняется, админ получает ошибку. Автору отправляются инструкция и (если задан) дополнительный текст.

### Выбор ссылки
- Общая (PMI), если ни одно занятие не пересекается с встречей на общей ссылке.
- Иначе отдельная комната (`use_pmi: false`), если ни одно занятие не пересекается с встречей на отдельной ссылке.
- Иначе одобрить нельзя (в слоте не больше двух встреч: общая и одна отдельная).
- Серия получает одну ссылку на все занятия: решение принимается по всем занятиям за горизонт 6 месяцев.
- События календаря, созданные не ботом, считаются занятыми общей ссылкой (календарь используется только для Zoom). События самого бота в календаре не учитываются повторно (сопоставляются по UID).

### Проверка занятости
- Учитываются: встречи бота в статусах «одобрена» и «отмена запрошена» и события календаря.
- События со статусом «свободен» (`TRANSP:TRANSPARENT`) и отменённые пропускаются; события на весь день и предварительные (`TENTATIVE`) считаются занятыми.
- Рабочих часов и буфера между встречами нет, границы точные (встык — не пересечение).
- Если календарь недоступен, заявка не принимается (нельзя «молча» считать время свободным).

### Zoom
- Разовая встреча — запланированная встреча (type 2); серия — встреча без фиксированного времени (type 3), одна постоянная ссылка на все занятия, расписание хранят бот и календарь. Способ создания серии изолирован в `services/series.py`.
- `use_pmi: true` для общей ссылки, `false` для отдельной комнаты. Пароль и зал ожидания берутся из профиля Zoom.
- OAuth: приложение типа General App (User-managed). Токены хранятся зашифрованно, refresh-токен обновляется под блокировкой (он одноразовый).

### Яндекс Календарь (CalDAV)
- Подключение: логин Яндекса и пароль приложения для календаря; бот удаляет сообщение с паролем и хранит его зашифрованным. Если календарей несколько, бот предлагает выбрать нужный.
- Для разовой встречи создаётся одно событие, для серии — отдельное событие на каждую выбранную неделю месяца (Яндекс не разворачивает несколько недель в одном `BYDAY`).
- Известное ограничение: для пары «4-я + последняя» в месяцах, где они совпадают, в Яндекс Календаре будут два одинаковых события (в Zoom и в расписании бота дубля нет). Яндекс неверно разворачивает `BYDAY=5xx` и `BYMONTHDAY`, поэтому обходной путь не используется; бот предупреждает автора в сводке заявки и админа в карточке. Сверка серии этот известный дубль учитывает.
- Время событий записывается с `TZID=Europe/Moscow`; в событии — название, комитет, ссылка на Zoom.
- Ссылка в событии, в карточках и списках такая же, как в сообщении автору. Уже созданные события при смене настроек ссылок не обновляются.

### Отмена
- Автор отменяет заявку «на рассмотрении» сам (лимит освобождается). Одобренную встречу автор отменяет через запрос; админ одобряет или отклоняет.
- Админ может отменить любую встречу сам (с подтверждением «Точно отменить?»).
- Серия отменяется только целиком. Нельзя отменить встречу, если занятие уже идёт или началось.
- Порядок: удалить в Zoom → удалить событие(я) в календаре → пометить отменённой → уведомить автора. Если шаг не удался, статус не меняется, админу сообщается, что сделано и что осталось; повтор безопасен («не найдено» в Zoom и календаре считается успехом).

### Сообщение с инструкцией
Шаблон один для всех встреч, админ редактирует его в боте; есть значение по умолчанию и сброс. Переменные:

`{title}`, `{committee}`, `{date}`, `{time}`, `{duration}`, `{join_url}`, `{join_short_url}`, `{meeting_id}`, `{passcode}`, `{author}`, `{recurrence}` (описание повтора, для разовых пусто).

Шаблон проверяется при сохранении (неизвестные переменные, синтаксис). Если сохранённый шаблон оказался некорректным, используется стандартный.

**Ссылки.** Админ может задать свои `{join_url}` и `{join_short_url}`. Если задана хотя бы одна — подставляются только заданные (незаданная остаётся пустой); ссылка из Zoom берётся, если не задана ни одна или встреча в отдельной комнате (в этом случае автору добавляется пометка, что ссылка не общая).

**Дополнительный текст** (`extra_text`) — одинаковый для всех встреч, отправляется автору **отдельным вторым сообщением** после инструкции (если не пустой). Переменной в шаблоне для него нет.

### Списки
- «Мои встречи»: название, комитет, ближайшая дата и время, статус, ссылка (для одобренных), повтор. Прошедшие не показываются; отклонённые — 3 дня.
- «Все встречи» (админ): заявки «на рассмотрении» выше остальных, дальше по ближайшей дате; по 10 на страницу; карточка с кнопками по статусу. Показываются статусы: на рассмотрении, одобрена, отмена запрошена.

## Установка и запуск

### Требования
Python 3.10+ (на хостинге использовался 3.11). Зависимости — в `requirements.txt`:
`aiogram>=3.7`, `SQLAlchemy[asyncio]`, `aiosqlite`, `aiohttp`, `caldav`, `icalendar`, `recurring-ical-events`, `python-dateutil`, `cryptography`.

### Переменные окружения (`.env.example`)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота из @BotFather |
| `ADMIN_IDS` | Telegram ID админов через запятую, например `123456789,987654321` (не перезаписывается при деплое) |
| `SETTINGS_KEY` | ключ шифрования Fernet (44 символа, base64) |
| `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET` | ключи приложения Zoom |
| `ZOOM_REDIRECT_URI` | `https://<ваш-домен>/zoom/callback` |
| `DATABASE_URL` | по умолчанию `sqlite+aiosqlite:///zoombot.db` |
| `PORT` | порт веб-сервера для OAuth-колбэка (по умолчанию 8080) |

Ключ шифрования:
```
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```
Его нужно задать один раз и не менять: им зашифрованы токен Zoom и пароль календаря. После смены ключа Zoom и календарь придётся подключать заново.

### Настройка Zoom
1. На marketplace.zoom.us: Develop → Build App → **General App**, управление **User-managed**, без публикации в Marketplace.
2. В Basic Information → OAuth Information укажите **OAuth Redirect URL** и добавьте тот же адрес в **OAuth Allow List**: `https://<ваш-домен>/zoom/callback` (только `https`, точное совпадение).
3. Client ID и Client Secret (пара Development, пока приложение не опубликовано) — в переменные окружения.
4. Scopes: `meeting:write:meeting` и `meeting:delete:meeting`. После изменения scopes Zoom нужно переподключить.

### Настройка Яндекс Календаря
Яндекс ID → Безопасность → Пароли приложений → создать пароль для «Календарь». Логин и этот пароль вводятся в боте.

### Первый запуск
1. Задайте переменные окружения, включая `ADMIN_IDS` (ваш Telegram ID можно узнать у @userinfobot).
2. `pip install -r requirements.txt`, затем `python main.py`.
3. В боте: `/start` → «Управление» → «Подключить Zoom» и «Подключить календарь».
4. Подайте тестовую заявку и одобрите её.

Бот работает через long polling и поднимает в том же процессе веб-сервер для OAuth-колбэка Zoom (домен должен быть доступен по HTTPS).

### Развёртывание на хостинге
Если файловая система контейнера не постоянна, положите БД в сохраняемую папку, например `DATABASE_URL=sqlite+aiosqlite:////app/data/zoombot.db` (абсолютный путь — четыре слэша). Запускайте **один экземпляр** бота: два процесса с одним токеном дают ошибку `Conflict: terminated by other getUpdates request`.

```
  handlers/

    request.py             диалог заявки (FSM), /request
    review.py              одобрить / отклонить / проверить занятость
    meetings.py            списки, карточки, отмена автором и админом
    admin_settings.py      Zoom, календарь, шаблон, доп. текст, ссылки
  callbacks.py states.py keyboards.py views.py notify.py filters.py
db/
  models.py                Meeting, Setting, Status, Link
  repo.py                  запросы, атомарная смена статуса, лёгкая миграция SQLite
services/
  zoom.py                  клиент Zoom: OAuth, создание/удаление встреч
  series.py                способ создания серий (заменяемая стратегия)
  caldav_client.py         чтение занятости, создание/удаление событий, список календарей
  availability.py          проверка занятости и выбор ссылки (общая/отдельная)
  recurrence.py            правила повтора, RRULE, описание, разворачивание на горизонт
  approval.py              одобрение с откатом
  cancellation.py          отмена в правильном порядке
  templating.py            шаблон инструкции, разрешение ссылок
  links.py                 заданные админом ссылки, единая ссылка для показа
  verification.py          сверка серии с календарём после создания
  refs.py crypto.py        хранение нескольких ссылок событий, шифрование

```

## База данных
SQLite, две таблицы: `meetings` (заявки и встречи) и `settings` (ключ-значение: токены Zoom, данные календаря, шаблон, дополнительный текст, ссылки). Время в БД — UTC. Колонки, добавленные в новых версиях (`link_kind`, `overlap_flag`), создаются в существующей базе автоматически при запуске.

## Безопасность
- Секреты только в переменных окружения; токен Zoom и пароль календаря в БД зашифрованы (Fernet).
- Сообщение с паролем календаря бот удаляет сразу после получения.
- Админские действия проверяются по `ADMIN_IDS` на каждом нажатии кнопки.
- Любая смена статуса идёт одним атомарным `UPDATE ... WHERE status = ...`: если заявка уже обработана в другом месте, бот отвечает «Заявка уже обработана».

## Известные ограничения
- Состояние диалогов (FSM) и OAuth хранится в памяти: после перезапуска бота незаконченные заявки и настройки сбрасываются (сохранённые в БД заявки остаются).
- Бот рассчитан на один процесс.
- Запрос на отмену уходит всем админам отдельными сообщениями; после обработки одним у остальных кнопки остаются, но нажатие даст «Запрос уже обработан».
- Ссылки в уже созданных событиях календаря не обновляются при смене настроек ссылок.
- Поведение Яндекс Календаря с разворачиванием серий (события по неделям, `BYMONTHDAY`) зависит от сервера Яндекса и версии библиотеки `caldav`; поэтому после создания серия сверяется с ожидаемыми датами.
- Идея на будущее (не реализована): разбор текстовых запросов через ИИ (GigaChat).

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Fernet key must be 32 url-safe base64-encoded bytes` | `SETTINGS_KEY` задан не в формате Fernet; сгенерируйте ключ командой выше |
| `Conflict: terminated by other getUpdates request` | тот же токен используется в другом процессе; один токен — один экземпляр |
| Zoom: ошибка 4700 «Неверный идентификатор клиента» | неверный `ZOOM_CLIENT_ID` (не та пара ключей, лишние символы, не General App) |
| Zoom: 4711 «Invalid access token, does not contain scopes» | в приложении нет `meeting:write:meeting`; добавьте scopes и переподключите Zoom |
| Redirect URL: «A secure URL using HTTPS is required» | в поле адрес без `https://` или с пробелом |
| «Управление» показывает список встреч вместо настроек | ваш Telegram ID не в `ADMIN_IDS` (в логе при запуске будет предупреждение, если переменная не задана) |
| Нет новых кнопок в меню | работает старая версия или нужно заново нажать `/start` |
